# 01. 需求规格

## 1. 用户故事（User Stories）

### 资料摄取
- 作为用户，我可以上传 PDF / Word / PPT / Excel / Markdown 文件，系统自动解析并建立索引。
- 作为用户，我可以粘贴一个网址（单页或文档站点如 docs.xxx.com），系统抓取该页面及其子页面并建立索引。
- 作为用户，我可以粘贴一个 GitHub 仓库链接，系统拉取代码与文档并建立索引，理解项目结构。
- 作为用户，我可以把多个资料源组织在同一个"学习空间/课程"下，作为一个整体学习单元。
- 作为用户，我可以查看每个资料源的摄取状态（排队中/解析中/已完成/失败），失败时能看到原因并重试。
- 作为用户，当我发现资料不足时，我可以**主动要求 Agent 联网搜索**补充资料（如"去网上找一些关于 XX 的资料补进来"），Agent 返回候选网页列表，我确认后才将其纳入学习空间。
- 作为用户，我能清楚区分哪些资料是我自己提供的、哪些是联网检索补充的，并可以单独删除后者。

### 问答
- 作为用户，我可以针对某个学习空间提问，Agent 基于其中的资料回答，并标明引用了哪些资料/段落/文件。
- 作为用户，当资料不足以回答我的问题时，Agent 应明确告知，而不是编造答案。
- 作为用户，我可以选择"严格基于资料回答"或"资料优先、允许补充通用知识"两种问答模式。
- 作为用户，当 Agent 告知"资料未覆盖"时，我可以一键让它联网搜索并基于搜索结果回答，答案需明确标注哪些内容来自互联网及其链接。
- 作为用户，我可以在多轮对话中追问、要求换个角度解释、要求给出例子。

### 学习计划
- 作为用户，我可以基于某个学习空间一键生成学习计划，输入我的目标（如"两周后考试""每天 1 小时"）。
- 作为用户，学习计划应该分阶段/分主题，并标明每个阶段对应哪些资料章节。
- 作为用户，我可以标记某个学习阶段"已完成"，计划应能感知我的进度并调整后续安排（如落后时压缩非核心内容）。
- 作为用户，我可以要求重新生成或调整计划（如"我基础比较好，跳过入门部分"）。

### 题库与测验
- 作为用户，我可以基于某个学习空间/某个阶段生成题目（选择题、填空题、简答题；若为代码仓库还应支持编程题/读代码题）。
- 作为用户，我可以设置题目难度、数量、题型分布、覆盖的知识点范围。
- 作为用户，我可以进入"测验模式"限时作答，系统自动批改客观题，AI 批改主观题并给出评语。
- 作为用户，我答错的题目会进入"错题本"，系统按间隔重复（spaced repetition）提醒我复习。
- 作为用户，我可以查看每道题目关联的知识点和资料出处，点击可跳转回原文。

### 系统讲解 / Lecture
- 作为用户，我可以要求 Agent 对某个主题做"系统性讲解"，按知识点的先后依赖顺序讲清楚，而不是零散回答。
- 作为用户，我可以要求生成整个学习空间的知识大纲/知识图谱，了解主题之间的关系。
- 作为用户，我可以进入"Lecture 模式"，Agent 像上课一样分节讲解，每节讲完提出 1-2 个检验性问题，回答后再继续下一节。
- 作为用户，我可以随时打断 Lecture 提问，问完后能回到讲课进度继续。

### 进度与账户
- 作为用户，我可以看到自己在某个学习空间的整体掌握度（按知识点/章节维度）。
- 作为用户，我可以注册/登录，我的学习空间、对话历史、题库、进度是持久化且仅我可见的（除非我主动分享）。

## 2. 功能性需求（Functional Requirements）

| ID | 需求 | 优先级 |
|---|---|---|
| FR-1 | 支持上传 PDF/Word(.docx)/PPT(.pptx)/Excel(.xlsx)/Markdown 文件并解析为结构化文本 | P0 |
| FR-2 | 支持输入网址，抓取单页或递归抓取文档站点（同域名下的子页面），可配置抓取深度/范围 | P0 |
| FR-3 | 支持输入 GitHub 仓库 URL，克隆/拉取仓库内容，区分代码文件、文档文件、配置文件 | P0 |
| FR-4 | 资料解析后自动分块（chunking）、生成向量嵌入并写入向量库，支持增量更新（重新摄取变化的资料） | P0 |
| FR-5 | 用户可创建多个"学习空间"，每个空间可关联多个资料源，空间间数据隔离 | P0 |
| FR-6 | 提供基于 RAG 的问答接口，返回答案需附带引用来源（文件名+片段/页码/行号） | P0 |
| FR-7 | 问答支持多轮上下文、支持流式输出（SSE/WebSocket） | P0 |
| FR-8 | 问答需具备"资料未覆盖该问题"的显式判断与提示能力 | P0 |
| FR-9 | 支持生成结构化学习计划：分阶段、每阶段关联资料章节/知识点、预估耗时 | P0 |
| FR-10 | 学习计划支持根据用户输入的约束（截止日期、每日可用时间、已有基础）个性化生成 | P0 |
| FR-11 | 学习计划支持进度打卡与动态调整（重新生成剩余部分） | P1 |
| FR-12 | 支持基于资料生成题目：至少覆盖单选、多选、填空、简答四种题型 | P0 |
| FR-13 | 针对代码类资料（GitHub repo），支持生成代码阅读理解题/简单编程题 | P1 |
| FR-14 | 支持测验模式：限时作答、自动批改客观题、AI 批改主观题并生成反馈 | P0 |
| FR-15 | 错题自动归档进"错题本"，按遗忘曲线安排复习提醒 | P1 |
| FR-16 | 每道题需关联知识点标签与资料出处，支持从题目跳转回原文 | P1 |
| FR-17 | 支持"系统讲解"模式：围绕某主题按知识点依赖顺序生成结构化讲解内容 | P0 |
| FR-18 | 支持生成学习空间的知识大纲/知识图谱（主题-子主题-依赖关系） | P1 |
| FR-19 | 支持"Lecture 模式"：分节讲解 + 节间检验提问 + 允许打断提问后恢复讲课进度 | P1 |
| FR-20 | 提供用户维度的知识点掌握度追踪，随问答/测验结果更新 | P1 |
| FR-21 | 用户注册/登录/鉴权，数据按用户隔离 | P0 |
| FR-22 | 资料摄取为异步任务，前端可查询任务状态（排队/进行中/成功/失败+原因） | P0 |
| FR-23 | 支持配置/切换 LLM 供应商（如 OpenAI、Anthropic、本地 Ollama），不硬编码单一供应商 | P1 |
| FR-24 | 支持删除资料源/学习空间，并联动清理向量库中的相关数据 | P0 |
| FR-25 | 支持**用户主动触发**的联网搜索：给定查询词/当前问题，调用搜索服务返回候选网页（标题+摘要+URL） | P1 |
| FR-26 | 用户可从搜索候选中挑选若干条，将其网页正文抓取并作为新资料源纳入当前学习空间（复用 URL 摄取管线） | P1 |
| FR-27 | 联网检索得到的资料源需带 `origin=web_search` 标记，在 UI 中与用户自有资料明确区分，并可单独筛选/删除 | P1 |
| FR-28 | 联网搜索**不得自动触发**：必须由用户显式操作（按钮/明确指令）发起；系统需提供开关，管理员/用户可全局禁用该能力 | P1 |
| FR-29 | 基于联网结果生成的回答/题目/讲解，需标注来自互联网的内容及其原始 URL，与本地资料引用视觉上可区分 | P1 |

## 3. 非功能性需求（Non-Functional Requirements）

| ID | 需求 | 说明 |
|---|---|---|
| NFR-1 | **可溯源性** | 所有教学产物（问答/题目/讲解）尽可能标明资料出处，出处链路要能在前端点击定位 |
| NFR-2 | **低幻觉** | 通过 RAG + 严格的系统提示 + 引用校验，降低无依据编造内容的概率；无法回答时应明确说明 |
| NFR-3 | **响应体验** | 问答与 Lecture 内容以流式（streaming）方式返回，首字节延迟（TTFB）应在可接受范围（如 < 2s） |
| NFR-4 | **可扩展性** | 新增资料类型（如视频字幕、电子书）、新增题型、替换向量库/LLM 供应商时改动应局部化 |
| NFR-5 | **数据隔离与隐私** | 用户资料、对话、题库默认仅本人可见；系统需支持对接自托管/本地模型以满足隐私敏感场景 |
| NFR-6 | **可观测性** | 摄取任务、Agent 调用链路（尤其是多 agent/多工具调用）需要可追踪日志，便于调试和成本分析 |
| NFR-7 | **成本可控** | 需对 embedding/LLM 调用做用量统计；长文档/大仓库摄取需考虑分批处理与限流，避免一次性超大开销 |
| NFR-8 | **可测试性** | 核心链路（摄取、检索、题目生成、批改）需有自动化测试覆盖，避免 prompt 改动导致质量回退难以发现 |
| NFR-9 | **国际化** | 至少支持中文/英文两种界面与生成内容语言（资料语言与用户提问语言可能不同，需要处理跨语言问答） |
| NFR-10 | **安全性** | 网址抓取需防范 SSRF；GitHub 仓库拉取需限制大小/超时；文件上传需校验类型与大小、防范恶意文件 |
| NFR-11 | **联网内容的可信度** | 联网检索的资料质量不可控（可能过时、错误、含提示注入内容）。需：①网页正文作为**数据**而非**指令**处理，防范间接提示注入；②在 UI 与引用中始终标明来源域名与抓取时间，让用户自行判断可信度；③搜索来源域名支持白名单/黑名单配置 |

## 4. 约束条件

- GitHub 仓库可能很大，需要有大小/文件数上限和可配置的忽略规则（如 `.gitignore`、二进制文件、`node_modules` 等），可参考 gitingest / repomix 的过滤策略。
- 网址抓取需要遵守 `robots.txt`、设置合理的并发与超时，避免被目标站点判定为爬虫攻击。
- 单个学习空间的资料总量、单次生成的题目数量等应有可配置上限，防止单用户过度消耗资源。
- LLM/embedding 调用为外部依赖，需要有超时、重试、降级（如 embedding 失败时的重试队列）机制。
- 搜索服务（如 Tavily/Brave/SerpAPI 等）为付费外部依赖，需要按用户限流与用量统计；搜索能力应可通过配置整体关闭（离线/私有化部署场景下不可用是正常状态，不应导致其他功能不可用）。
